| 2026-10-16 | **What a comma in a number means is decided per column** (`lm_profile::number_style`), from all its cells as written. Cells grouped like `^-?\d{1,3}(,\d{3})+(\.\d+)?$`, with at least one having two groups or a decimal point (`1,250,000`, `12,500.50`) → thousands separators. A comma followed by other than exactly three digits, or with more than three digits before it (`121,473701`, `12,5`, `1234,50`) → decimal comma. Every comma cell `d,ddd` and nothing else telling → decimal comma if the file is `;`-delimited, otherwise **not guessed**: those cells stay text and the field's role evidence says why. Both unmistakable kinds in one column → text. A lone cell (`parse_number`) parses only when unmistakable (`12,500` alone → no number). The lm-jobs CSV reader types and locates rows with the same per-column style. **Proposed catalog row for the owner:** "Numbers with commas" · Detection: the rule above · Treatment: Silent when the cells tell; when they can't, kept as text, noted in the field list · Line: "Kept as text: 12,500 could mean twelve thousand five hundred or twelve and a half. Change". | Independent review (S1): `12,500` was read as 12.5, so a population column came out 1,000× too small, silently. No assumption kind was added (catalog first). | Owner: accept or reword the proposed row; then add a kind and a Change (read as thousands / as decimals). |
